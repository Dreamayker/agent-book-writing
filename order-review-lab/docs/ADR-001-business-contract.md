# ADR-001：订单教学工程的首版业务口径

状态：已采用为教学工程契约。日期：2026-11-05；规则版本 `order-rules-v1`。这些取舍是工程实现口径，不代表虚构公司的真实业务批准。

系统以活动价为输入，只支持品类、满减、新人三种券，每类最多一张。在用户提交的候选券内比较合法方案；活动价→品类→满减→新人，互斥时分别计算满减和新人路径，以最终实付最低者胜出，同额优先满减路径。接口返回各阶段基数、实际抵扣及排除原因。

所有金额为 `long` 整数分，单价及整单上限均为 `10^12` 分（100 亿元），中间分摊乘积使用 `BigInteger`。比例优惠用整数基点表示，在每一券阶段对合格总额向下取整一次，再用最大余数法分至购买单位；余数相同按商品 ID 和补零单位序号排序。每行最多 100 件、整单最多 1000 件，每阶段封顶到可参与商品的剩余实付，记录封顶事件。

价格、品类、新人资格及券所属用户来自服务端固定适配器。客户端仅传商品 ID/数量和候选券 ID。券必须属于当前用户且未过期；新人身份不合格的券从候选集排除。不支持运费、积分、税费和券返还。

快照冻结每个购买单位的实付与分摊，退款只接受单位 ID，每单位最多退一次。拆单必须是原单位的完整不重叠划分，子单引用同一根订单及单位账本，父子单退款共享额度。已退款订单不能拆单，同一订单只能直接拆一次，子单可以继续完整拆分。

订单提交、券消费、快照、幂等记录在一个事务中提交。首版用数据库用户行锁串行化同用户写入，并在退款时锁根订单；唯一约束、单位状态条件更新和累计额度条件更新构成额外保护。它牺牲同用户吞吐量换取可解释的教学基线，不宣称已经完成生产支付、券库存或分布式事务设计。

幂等键按用户和操作作用域隔离，退款及拆单操作同时包含订单 ID。相同键和请求返回原结果，不同请求冲突；失败事务回滚，不落成功结果。没有可信快照或快照校验失败的历史订单进入 `MANUAL_REVIEW`，禁止按实时规则补算。快照 SHA-256 用于检测内容意外改变，不构成可抵抗数据库管理员篡改的签名。

首版没有真实支付调用：提交后视为教学场景的已付订单，退款落内部记录，无资金出站。`X-User-Id` 是只在本地沙箱使用的身份适配头，生产环境必须替换。Redis 未参与正确性链路。
