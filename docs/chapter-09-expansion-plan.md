## 写作约束

每个分子章节必须包含四层内容：先给出可辩护的核心观点，再解释工程机制和适用边界，然后用项目内可复现案例佐证，最后明确读者能够执行或判断什么。案例必须引用需求、错误 Diff、工具输出、Finding、人工裁决或修复验证中的至少两类证据。录制回放只能说明控制面正确，不能写成真实模型能力。

正文避免按概念百科堆砌字数。每增加一个结论，都要回答“依据是什么、如何复现、在哪些条件下不成立”。

## 案例展开模板

每个完整案例统一按以下顺序写入正文：

1. 业务需求与不可违反的不变量。
2. 错误变更的最小 Diff，以及为什么代码审阅时容易忽略。
3. 测试、Semgrep、OSV 或策略守卫的原始关键输出。
4. 专业 Agent 产生的结构化 Finding。
5. 仲裁如何处理重复、冲突和人工门禁。
6. 人工裁决及其责任边界。
7. 修复 Diff 与回归验证。
8. 从教学实现迁移到生产系统时不能直接照搬的部分。
