# ADR-003：模型数量、角色复用与评测策略

- 状态：已采纳，实时实验待执行
- 日期：2026-08-16

## 背景

评审系统包含通用、正确性、测试、安全、影响分析和仲裁角色，但 Agent 数量不等于模型种类。为每个角色绑定不同模型会显著增加配置和实验成本；全部角色共用一个模型又会增加相关性偏差。

## 决策

采用分阶段策略：

1. 一个模型即可验证实时调用和多角色流程。
2. 出版级实验推荐两种模型：模型 A 执行专业评审，模型 B 独立仲裁或复验。
3. 第三种模型只用于跨模型稳健性补充，不作为系统硬依赖。
4. 同时保留 Recorded Agent，使控制面测试不依赖商业 API。
5. 每种真实配置对每个案例运行 3～5 次，并记录模型版本、提示词、Token、延迟、成本和波动。

## 实验矩阵

- 单 Agent：模型 A。
- 多角色同模型：模型 A。
- 多角色同模型 + 同模型仲裁：模型 A。
- 多角色 + 异模型仲裁：模型 A 工作、模型 B 仲裁。
- 可选跨模型复验：模型 B 或模型 C 独立评审。

## 后果

积极影响：最小配置简单，同时能通过异模型仲裁研究相关性偏差。

代价与限制：两种模型会增加成本和供应商差异；没有 API Key 前只能验证请求适配器与录制控制面，不能声称获得真实模型 Precision 或 Recall。
