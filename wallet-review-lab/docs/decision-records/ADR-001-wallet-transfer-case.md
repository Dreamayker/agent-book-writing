# ADR-001：选择数字钱包转账作为贯穿案例

- 状态：已采纳
- 日期：2026-08-16

## 背景

原章节使用优惠券计价系统说明金额、权限、并发和测试问题，但案例容易扩散到会员、叠加和营销规则，读者需要先理解大量业务设定。章节需要一个代码规模可控、风险清楚、可以建立标准答案的贯穿案例。

## 决策

采用虚构的数字钱包转账服务作为主案例。系统只处理测试钱包和虚构金额，不连接真实支付网络。业务核心限定为查询钱包和执行转账，并建立四条不变量：金额守恒、余额非负、请求幂等和源钱包授权。

## 理由

- 金额精度、对象级授权和并发双花都来自同一个核心用例。
- 幂等和事务是 API 评审中具有代表性的工程问题。
- 资金类变更天然适合说明高风险人工终审。
- 项目可控制在一章能理解的代码规模内。
- 可通过失败测试和静态规则构造明确 Oracle。

## 后果

积极影响：案例主线集中，多个 Agent 可以围绕同一业务对象提供互补证据。

代价与限制：案例不能代表真实支付清算、会计分录、多币种和监管系统；正文必须明确其教学边界，不能将内存锁方案写成生产级支付架构。
