## 三、结构调整理由

1. **相对原稿 9.1–9.10 骨架**：原稿按"任务类型→多 Agent→测试/安全协同→投票仲裁→摘要影响→误报漏报→成本→触发策略→评测→真实实验"排列，呈现的是写作推进顺序而非知识依赖顺序。本版改为"**原理→实验场→单 Agent→多 Agent→流水线→实战→治理→评测→生产→演练**"，读者先建立判断标准（Oracle、不变量、契约），再进入复杂机制。

2. **"出版扩展"并入正文**：原稿把任务契约与四种不确定性放在文末扩展。这两者正是读者理解 Agent 边界的前提，前移为 9.1.4 与 9.3.2。

3. **原稿重复内容收敛**：评审顺序（9.3/9.4 重复）、路由规则（9.9/9.10 重复）、成本（9.8/9.9 分散）分别收进 9.5、9.8、9.8.4；PR 摘要纪律收进 9.3.3，应用保留在 PR-05。

4. **六案例合并为一个大节（9.6）**：PR-04 在 9.4.4 只做配置对比、9.7.2 只做仲裁引用，完整教学只在 9.6.4 出现一次，避免每处重讲整案。

5. **新增生产与演练两节（9.9、9.10）**：原稿只有"从回放走向真实模型实验"的短段落与一条阅读路线。9.9 补齐影子模式、监控、回滚、生产待验证；9.10 把阅读路线升级为可交付演练，衔接任务书要求的六类交付物。
