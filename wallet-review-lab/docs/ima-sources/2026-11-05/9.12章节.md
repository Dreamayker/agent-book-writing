# 9.12 端到端演练：让一个订单变更走完证据闭环

## 9.12.1 准备正确业务与评审环境

从仓库根目录分别执行 Java 和 Python 门禁：

```bash
cd order-review-lab
./mvnw -B -ntp clean verify
python3 scripts/check_coverage.py
cd ../wallet-review-lab
uv sync --extra dev --locked
uv run pytest
uv run ruff check .
uv run mypy app review_system evaluation
```

Java 集成测试需要 JDK 17 和 Docker，使用真实 MySQL。Python 检查验证钱包历史兼容及共享评审流程。不要把任何一组全绿外推为覆盖了所有业务或攻击场景。

## 9.12.2 先盲读 ORD-09

只打开 requirement.md、buggy.patch、raw/buggy-source.txt 与失败测试输出，暂不读 Oracle、fixed.patch 或录制 Finding。计算 A/B/C 的实付，写下你认为被破坏的不变量、代码位置和修复方向。

观察错误调用 quote 如何跨越时间边界：订单使用规则 v1，下单后实时规则变为 v2，退款却没有固定到 v1。失败日志给出 expected 6600 but was 6400；这是一项教学构造，但失败与修复均为真实执行。

## 9.12.3 重放错误和修复版本

```bash
cd order-review-lab
python3 scripts/replay_cases.py verify --case ORD-09
```

脚本从 case.yaml 指定基线创建独立 worktree，检查并应用错误补丁，保存实际变更提交，运行目标 MySQL 测试，再应用修复、验证源码恢复正确基线并重跑。observed.yaml 记录两次执行的命令、退出码和耗时，原始日志原样保存。

错误版本应出现退款金额差异；修复版本打印 expected=6600 actual=6600，且 livePricingReadsDuringRefund=0。若日志显示缺少 Docker、网络失败或编译错误，先修复环境，不能把它写成发现退款缺陷。

## 9.12.4 经过三种评审模式

```bash
cd wallet-review-lab
uv run python -m evaluation.projects ../order-review-lab/evaluation/cases.yaml --mode single
uv run python -m evaluation.projects ../order-review-lab/evaluation/cases.yaml --mode multi
uv run python -m evaluation.projects ../order-review-lab/evaluation/cases.yaml --mode multi_arbitrated
```

三次读取相同录制控制夹具。single 的空列表故意模拟漏报，multi 的多个预设意见可能重复，multi_arbitrated 合并相同根因。高风险 ORD-09 在所有模式下都应 escalate；ORD-01 零缺陷文档样本不应被错误阻断。

这些差异证明模式、证据门禁和评分代码可运行，不构成模型能力比较。检查输出 kind=recorded-control-fixture，不能把夹具的完美命中写成真实 Recall。

## 9.12.5 人工复核与副线练习

对照 Oracle 后，检查修复是否恢复了快照不变量，而不是只满足一个金额样例。再阅读 splitKeepsOriginalSharesAndSharedRefundLedger：子单退 C 后父单必须拒绝再次退同一单位。最后重放 ORD-04，解释为什么数据库锁与单位状态门禁缺一不可。

human-verdict.yaml 仍标为 pending-human-review。由实际审查者填写版本、理由、证据和责任；不要用虚构签名完成流程。第 10 章可使用 ORD-09 冻结事故版本深入展开诊断、反例生成与最小修复。

## 9.12.6 真实模型实验另行验收

先明确两个模型名、兼容端点能力和总预算，再对 ORD-01/09 小范围试跑，记录成功、失败、拒答、usage 和延迟。之后按 9.9 的重复实验矩阵扩展，并将源码发现与证据解释两轨分开。

当前可以独立重放的是业务正确性、缺陷反例、修复、录制评审和策略门禁。真实模型效果与费用只有在保存完整调用台账后才能补入正文；工程完成不等于全部实验和出版审校已经完成。
