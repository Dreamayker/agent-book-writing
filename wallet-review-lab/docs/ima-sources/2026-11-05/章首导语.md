# 章首导语

本章把"AI 代码评审"从一个模型输出质量的问题，重构成一个工程系统的问题：怎样把模型放进一条可验证、可回放、可审计、可问责的证据流水线，让每一次评审结论都能追溯到缺陷证据、不变量与人工裁决。围绕这个目标，本章回答三个问题：

- **评审为什么需要证据而不是意见？** 模型说"这段代码有并发问题"，和它能拿出"在哪条执行轨迹上、违反哪条不变量、用什么测试复现"，是两回事。前者是意见，后者才是可以被复核、被回放、被问责的证据。

- **多个 AI Agent 如何分工、如何仲裁？** 单一模型在单个任务上能力不足，专业化分工能提升覆盖率，但分工必然带来意见冲突。本章给出最小角色集、仲裁协议与人工治理的边界。

- **怎么证明这套系统可信？** 通过统一 Finding Schema、证据包、录制回放与双层 Oracle 评测，把"模型说得对不对"变成可测量的指标，而不是印象。

全章围绕一个可复现的实验场展开：**wallet-review-lab**，一个刻意保留缺陷的数字钱包仓库。它的四条业务不变量——金额守恒、余额非负、幂等键单次生效、对象所有权——构成评审、仲裁与评测的共同语言，本章每个案例都围绕其中一条或多条展开。
