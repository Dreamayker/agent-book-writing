# 9.9 Token 成本与触发策略

[返回第 9 章目录](README.md)

成本边界本质是风险预算。低风险 PR 的错误阻断主要损害效率，高风险 PR 的漏报可能损害资产和信任。同样的模型费用在两类 PR 上价值不同。团队应先定义每类风险可接受的漏报、延迟和人工负担，再选择 Agent 组合。

路由规则应同时使用路径和语义标签。文档变更进入低风险路径；普通业务逻辑进入 correctness + test；命中 `money`、`authorization`、`credentials` 或 `database-transaction` 时提升为高风险。若人工标签或策略命中高风险，模型不得降级。

稳定的 Schema、团队规范和工具契约可以缓存；凭证、个人数据和生产日志不能缓存。下游 Agent 接收上游结构化摘要和证据引用，避免重复阅读完整 Diff；但压缩后的上下文必须保留状态边界、失败条件和修复约束。每次运行保存模型标识、提示词版本、Token、延迟、重试和最终决策，才能比较策略变化的真实成本。

## 深入：路由规则要可测试、可审计

路由规则是安全策略，不是提示词。每条规则都应有名称、来源、匹配条件、升级动作、例外审批和测试样例。比如删除 `owner_id` 比较，即使只有一行 Diff，也必须命中授权高风险；修改文档，即使位于核心目录，也不应自动触发数据库事务评审。规则组合采取只升不降：路径规则、语义规则、人工声明中任何一项升高风险，后续 Agent 不能把它降回低风险。

规则测试要包含边界和对抗样例。测试 `money` 标签命中金额模块，也要测试注释中的单词不会误触发高风险；测试 `docs/` 路径低风险，也要测试文档修改了权限策略时语义标签能够升级。每次规则变更保存前后路由矩阵，说明哪些 PR 会新增工具和人工负担。

路由结果应可解释：命中了哪些规则、来自哪一行 Diff、选择了哪些 Agent、哪些工具被跳过以及为什么。这样开发者可以修正标签或补充需求，而不是面对一个无法申诉的红灯。路由日志还可以发现系统性偏差，例如某个目录几乎总被错误升级，或某类安全变更经常没有进入人工门禁。
