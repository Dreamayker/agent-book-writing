# 9.6 PR 摘要、影响分析和风险标注

[返回第 9 章目录](README.md)

摘要回答“改了什么、为什么改”，影响分析回答“谁会变化、失败会怎样”。以 PR-05 为例，摘要应写明删除了服务端幂等键查询；影响分析则必须列出余额状态、转账记录、重试响应和幂等键约束四个受影响状态。只写“简化超时重试”会掩盖第二次扣款的风险。

风险标签建议使用 `must_fix`、`concern` 和 `nitpick`。PR-02 的浮点金额归一化可能通过普通测试，却违反货币精度策略，适合作为“测试通过不代表设计正确”的对照案例；PR-07 的依赖降级则需要查询 OSV 等外部事实，不能由模型记忆漏洞版本。标签是注意力排序，不是批准授权。

一份合格的 PR-05 摘要还应明确写出：变更意图是简化客户端重试；关键变更是删除服务端幂等查询；受影响状态包括两侧余额、转账记录、幂等键映射和重试响应；普通转账已验证，但相同键重试失败，两个相同键请求并发到达尚未验证。把“已验证”和“未验证”分开，才能防止摘要制造虚假的完整感。

## 深入：摘要和影响分析必须带边界标签

PR 摘要最危险的地方是它容易把“做了什么”写成“因此安全”。建议把每条结论分为 `verified`、`inferred`、`unverified` 三类。`verified` 只能来自本次运行的工具或人工确认；`inferred` 是基于代码结构的解释；`unverified` 是明确尚未覆盖的范围。PR-05 可以写“顺序重试的余额变化已验证”，同时写“跨进程并发首次请求未在教学实现中验证”。

影响图不只是调用图。对钱包转账，至少要画出输入参数、身份主体、源钱包、目标钱包、余额、转账记录、幂等映射和外部通知等节点，并标注读写关系。PR-04 的锁边界变化会同时影响余额和记录；PR-05 的幂等查询变化会影响重试响应和唯一键约束。这样的图能帮助 Agent 发现“修复了余额但漏了记录”的不完整补丁。

跨仓库影响必须诚实。当前实验仓库没有生产消息总线、异步消费者或第三方结算服务，因此不能声称这些调用方不存在。可以提供一个生产迁移清单：导出接口注册表、查询事件消费者、核对数据库迁移顺序、检查回滚兼容性、让服务所有者确认。影响分析的价值不是制造完整感，而是把未知范围变成下一步工作。
